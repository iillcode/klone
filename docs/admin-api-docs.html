KloneAdmin

Administration & Template Management API
Document Ref: KX-ADMIN-2026
Last Updated: Aug 12, 2026
v2.0 STABLE

1. Overview

The Klone Admin API powers the internal administration console (apps/admin). It is implemented as a set of Next.js Server Actions rather than a traditional REST surface — each action is invoked from a React Server Component or client component via the "use server" entry points in app/actions. All actions execute in a Supabase-authenticated server context and are protected by middleware.ts, which requires a valid session for any /dashboard/* route.

1.1 Core Responsibilities

  • Authenticate admin users via Supabase Auth (email + password).
  • Create, update and read reusable PDF document templates.
  • Persist template blueprints to public.pdf_templates.
  • Validate and coerce the JSON blueprint submitted from the editor.

2. Authentication

Every admin action runs in a session established by Supabase Auth. The verifySession() helper in lib/auth.ts reads the current user and redirects unauthenticated requests to /login. Actions below assume a valid cookie-based session is present.

ACTION login
Sign in with email & password; redirects to /dashboard on success.
ACTION logout
Sign out the current session; redirects to /login.

2.1 login(email, password)

Defined in app/actions/auth.ts. Accepts a FormData payload, authenticates with signInWithPassword, and redirects to /dashboard on success or returns an { error } state on failure.

Field Type Required Description
email string Yes Admin account email. Coerced to string from the form field.
password string Yes Account password passed to Supabase Auth.

2.2 logout()

Defined in app/actions/auth.ts. Calls supabase.auth.signOut() and redirects to /login. Returns void.

3. Template Management

Templates are stored in public.pdf_templates as JSON blueprints (page constraints + reusable component blocks) that the MCP server later serves to AI agents. The actions below live in app/actions/templates.ts and share a TemplateState return type: { error?: string; ok?: boolean }.

ACTION createTemplate
Insert a new pdf_templates row from form data.
ACTION updateTemplate
Update an existing template by id.

3.1 createTemplate(formData)

Reads common fields via readCommon(), validates the name and blueprint, then inserts into pdf_templates. On success it calls revalidatePath("/dashboard/templates") and returns { ok: true }.

Field Type Required Description
name string Yes Human-readable template name. Also used to derive the slug.
slug string No URL-safe identifier. Auto-generated from name if omitted.
description string No Optional summary of the template's purpose.
category enum No One of TEMPLATE_CATEGORIES (General, Reports, Business, Technical, Education, Legal, Personal).
tags string No Comma-separated list; split into the text[] column.
is_active boolean No "on" or "true" enables the template.
blueprint JSON string Yes Raw TemplateBlueprint JSON, validated by parseBlueprint().
preview_html string No Self-contained sample HTML assembled from the template's components.

3.2 updateTemplate(formData)

Same field set as createTemplate plus a required id. Updates the matching row and revalidates both the list and detail paths.

Field Type Required Description
id string (uuid) Yes Primary key of the template to update.
All fields from createTemplate Re-applied to the existing row (name, slug, blueprint, etc.).

4. Data Layer (Server Reads)

The server-only helpers in lib/data.ts provide direct, read-only access to pdf_templates. They are consumed by dashboard pages and are not exposed as standalone endpoints.

Function Returns Description
getTemplates() TemplateRow[] All templates ordered by name.
getTemplate(id) TemplateRow | null Single template by id, or null if not found.

5. Blueprint Schema

The blueprint JSON field conforms to TemplateBlueprint (see lib/template-types.ts). It is validated and coerced by parseBlueprint() before persistence.

Property Type Description
version number Blueprint schema version (currently 2).
page object Page constraints: format, content_width, margin, body_background.
structure string HTML scaffold containing a <!--content--> placeholder.
components array Reusable blocks, each with key, name, html, css, guidance, required, tags.
requirements array Global assembly constraints for the final document.

Error Responses

  • { error: "Template name is required." } — name missing.
  • { error: "Blueprint JSON is invalid." } — parse or shape failure.
  • { error: "Missing template id." } — update with no id.
  • { error: "<supabase message>" } — database insert/update failure.
